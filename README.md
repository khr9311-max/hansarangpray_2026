# 사랑의교회 청년부 한반도이웃사랑선교국 2026 짝기도 매칭

QR로 신청을 받아 짝을 지어주고, 빔프로젝터 화면에서 추첨하듯 조를 공개하는 현장용 웹앱.

**배포 링크**: https://hansarangpray-2026.vercel.app

- **프레임워크** Next.js 15 (App Router · Server Actions)
- **DB** Supabase (PostgreSQL + Realtime)
- **스타일** Tailwind CSS v4
- **호스팅** Vercel

## 화면

| 경로 | 링크 | 용도 |
| --- | --- | --- |
| `/` | [바로가기](https://hansarangpray-2026.vercel.app) | 참가자 입력 폼. QR로 진입하는 모바일 화면 |
| `/admin` | [바로가기](https://hansarangpray-2026.vercel.app/admin) | 관리자 대시보드. 접수 현황 · 매칭 실행 · CSV · 데이터 삭제 |
| `/display` | [바로가기](https://hansarangpray-2026.vercel.app/display) | 빔프로젝터 송출 화면. **모두에게** 보이는 화면 — 이름만 나옵니다 |
| `/me/[참가자id]` | — | 참가자 개인 링크. **본인과 기도짝에게만** 보이는 화면 — 조원들의 기도제목이 나옵니다 |

`/admin`에서 매칭을 확정하면 `/display`가 Realtime으로 즉시 갱신됩니다. 새로고침이나 폴링이 필요 없습니다.

### 기도제목은 기도짝끼리만

기도제목은 두 곳에서만 보입니다: **관리자 화면**(전체 관리용)과 **본인의 개인 링크** `/me/[id]`(자기 조 안에서만). 모두가 보는 `/display`에는 절대 나가지 않습니다.

신청 직후 뜨는 "내 기도짝 확인하기" 링크가 그 사람의 `/me/[id]`입니다. 이 링크는 브라우저에 12시간 동안 기억되므로, 새로고침하거나 나중에 다시 접속해도 빈 폼 대신 "이미 신청하셨어요 → 내 기도짝 확인하기" 화면이 뜹니다(같은 사람이 모르고 두 번 신청하는 것도 이걸로 막습니다). 폰을 빌려준 경우를 위해 "다른 분이 신청하시나요? 새로 신청하기" 버튼을 함께 뒀습니다. 매칭 전에는 "아직 매칭 전입니다"만 보이다가, 관리자가 매칭을 확정하면 Realtime으로 자동으로 자기 조 멤버들의 이름·팀·기도제목으로 바뀝니다. 다른 조 내용은 서버에서부터 아예 그 사람에게 전달되지 않습니다.

> **주의 — 진짜 인증은 아닙니다.** `/me/[id]`의 `id`는 추측하기 어려운 UUID일 뿐, 비밀번호나 로그인이 걸린 건 아닙니다. 링크를 다른 사람에게 전달하면 그 사람도 볼 수 있습니다. 로그인 없이 낮은 리스크로 개인화하는 절충안이며, 더 강한 보호(문자 인증 등)가 필요하면 별도로 알려주세요.

### 송출 화면의 추첨 연출

`/display`는 상태가 셋입니다.

1. **대기** — 신청한 이름표들이 통 안에서 둥둥 떠다닙니다. 새 신청이 들어오면 Realtime으로 이름표가 바로 추가됩니다.
2. **추첨 대기** — 관리자가 매칭을 확정하면 화면 아래에 **추첨 시작** 버튼이 뜹니다. 결과는 아직 감춰져 있습니다.
3. **결과** — 버튼(또는 `Space`)을 누르면 3초간 통이 흔들리며 이름표가 마구 섞이고, 그다음 조별 카드가 하나씩 튀어나옵니다.

진행자가 버튼을 누르는 시점을 잡을 수 있어서, 관리자가 미리 매칭을 확정해 두고 순서에 맞춰 공개할 수 있습니다. 결과 화면에서 `Space`를 다시 누르면 연출을 재생합니다. 새로고침해도 결과는 그대로 남습니다(연출만 건너뜁니다).

카드에는 **이름만** 나옵니다. 화면에 보이는 것뿐 아니라 페이지 소스(RSC 페이로드)에도 이름 외에는 실리지 않도록 서버 쪽에서 값을 잘라서 넘기고, React key도 실제 DB id 대신 화면 전용 가짜 값을 씁니다 — 실제 id가 그대로 노출되면 페이지 소스에서 모든 참가자의 `/me/[id]` 링크를 추출할 수 있게 되기 때문입니다.

## 입력 항목

| 항목 | 형태 |
| --- | --- |
| 이름 | 텍스트 (20자 이내) |
| 팀 | 드롭다운 — 영등포쪽방촌팀 · 단비팀 · 통일선교팀 · 운영팀 · 국장 · 교역자 |
| 기도제목 | 텍스트 영역 (500자 이내) |

팀 목록은 `NEXT_PUBLIC_TEAMS` 환경변수로 바꿀 수 있습니다.

## 매칭 방식

[`src/lib/matching.ts`](src/lib/matching.ts). 조 인원(2/3/4인) × 방식(2가지) = 버튼 6개.

- **팀 섞기 (`team`, 기본)** — 같은 팀을 최대한 피해 배치
- **완전 랜덤 (`random`)** — 아무 조건 없이 섞음

### 어떻게 겹침을 피하나

한 명씩 "지금 가장 덜 겹치는 조"에 넣는 그리디 배치입니다.

1. 인원이 많은 팀부터 한 명씩 번갈아 뽑아 **배치가 어려운 사람을 먼저** 처리합니다.
2. 각 사람마다 모든 조를 훑어, 같은 팀이 이미 있는 조일수록 벌점을 매겨 가장 낮은 조에 넣습니다.
3. 그리디는 시작 순서를 타므로 40회 돌려 충돌이 가장 적은 결과를 고릅니다. 충돌 0이 나오면 즉시 멈춥니다.

한 팀이 전체 인원의 절반을 넘으면 같은 팀끼리 겹치는 조가 수학적으로 반드시 생깁니다(비둘기집 원리). 그런 경우에도 겹치는 횟수를 이론적 최소치에 맞춥니다 — 예: 9명 중 3명이 한 팀이고 2개 조로 나누면 최소 1쌍은 반드시 겹치는데, 알고리즘이 정확히 그 최소치를 냅니다.

### 자투리 인원 — 깍두기

`computeGroupSizes()`가 **조별 인원을 먼저 계산**합니다. 정원을 채운 조를 만들고, 남는 사람은 조를 따로 만들지 않고 **깍두기로 기존 조에 한 명씩 끼워 넣습니다.** 정원 미달 조는 생기지 않습니다.

| 인원 | 2인 기준 | 3인 기준 | 4인 기준 |
| --- | --- | --- | --- |
| 7명 | 3, 2, 2 | 4, 3 | 4, 3 |
| 9명 | 2, 2, 2, 3 | 3, 3, 3 | 5, 4 |
| 11명 | 3, 2, 2, 2, 2 | 4, 4, 3 | 4, 4, 3 |
| 13명 | 3, 2, 2, 2, 2, 2 | 4, 3, 3, 3 | 5, 4, 4 |

예외가 하나 있습니다. 남는 인원이 조 수보다 많을 때(예: 3인 기준 5명 — 조는 1개인데 2명이 남음)는 기존 조에 다 몰아넣어 큰 조를 만드느니 작은 조를 하나 둡니다(5명 → `3, 2`). 1~200명 × 2/3/4인 전 구간을 검사해 합계·정수·양수를 확인했습니다.

셔플은 Fisher-Yates입니다. `sort(() => Math.random() - 0.5)`는 분포가 치우쳐서 쓰지 않았습니다.

## 준비

### 1. Supabase

새 프로젝트를 만들고 **SQL Editor**에 [`supabase/schema.sql`](supabase/schema.sql)을 붙여넣어 실행합니다. 테이블 4개(`participants`, `match_rounds`, `match_groups`, `match_members`), RLS 정책, Realtime 발행이 한 번에 설정됩니다.

RLS는 익명 사용자에게 **참가자 등록(insert)과 조회(select)만** 허용합니다. 매칭 실행·삭제는 서버 액션이 `service_role` 키로 수행하며, 그 전에 관리자 비밀번호를 검증합니다.

### 2. 환경변수

`.env.example`을 `.env.local`로 복사해 채웁니다.

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=        # 서버 전용. NEXT_PUBLIC_ 붙이지 말 것
ADMIN_PASSWORD=
NEXT_PUBLIC_TEAMS=영등포쪽방촌팀,단비팀,통일선교팀,운영팀,국장,교역자
```

### 3. 실행

```bash
npm install
npm run dev
```

## 배포

GitHub에 푸시하고 Vercel에서 Import → 위 환경변수 5개를 등록하면 끝입니다. 도메인과 SSL은 자동입니다.

배포된 URL(`https://<프로젝트>.vercel.app`)을 QR 생성기에 넣어 주보나 화면에 노출하세요.

## 현장 운용 순서

1. `/display`를 빔프로젝터에 띄우고 **F11**로 전체화면. 접수 중에는 안내 문구가 표시됩니다.
2. 참가자가 QR로 `/`에 들어와 이름·팀·기도제목을 제출합니다. 이름이 송출 화면 통 안에 바로 나타납니다. 제출 후 "내 기도짝 확인하기" 개인 링크가 뜨고, 폼은 감춰져 중복 제출이 걸러집니다.
3. `/admin`에서 접수 현황(팀별 인원)을 보며 마감 시점을 판단하고, 매칭 버튼을 누릅니다. 마음에 안 들면 다시 눌러 재매칭 — 이전 회차는 자동으로 내려갑니다.
4. `/display`에 **추첨 시작** 버튼이 뜹니다. 진행자가 누르면(또는 `Space`) 이름표가 섞이는 연출 후 조별 카드(이름만)가 공개됩니다.
5. 참가자는 아까 받은 개인 링크에서 자기 기도짝의 기도제목을 확인합니다.
6. 행사가 끝나면 **CSV 내려받기** 후 **전체 삭제**로 개인정보를 정리합니다.

    admin/

    display/
      page.tsx            송출 화면 (이름만 잘라서 클라이언트에 전달)
      DisplayStage.tsx    이름표 통 · 추첨 연출 · 조별 그리드
    api/admin/export/     CSV 내려받기 (UTF-8 BOM)
  components/
